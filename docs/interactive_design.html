数据管线

Data Flow

从用户输入到多格式导出的端到端管线，每个阶段均经过 Pydantic 校验。

01
👤 用户输入任务目标
用户通过对话界面定义 PR 任务目标，LLM 自动提取结构化 TaskMetadata，并生成澄清问题。
Pydantic 校验 LLM 提取
02
📄 品牌情报提取
上传品牌情报文档，通过 extract_from_document_via_llm() 解析，输出 InformationSearchReport JSON 结构。
LLM 解析 JSON Schema
03
🤝 人类确认策略
人类审阅提取的情报内容，确认或调整策略方向，结果捕获为 HumanConfirmation Pydantic 模型。
Human-in-the-Loop
04
🎯 Director 洞察生成
run_pr_director_insight() 输出品牌洞察、市场分析、PR 叙事方向、本土化建议与风险注记，生成 PRInsight。
五维分析 PRInsight 模型
05
✍ PR 稿件生成
run_pr_generation() 生成完整 PRDraftPackage：正文稿件、5 个标题选项、3 条社媒文案、媒体 Pitch Email、中文策略摘要。
多格式输出
06
🔍 四专家审阅 (x4)
run_all_reviews() 并行调用四个专职 Agent，每个返回结构化 ExpertReview，包含评分、问题与建议。
内容审阅 品牌审阅 创意审阅 法务审阅
07
🔄 修订与翻译
run_revision() 整合专家反馈进行 LLM 修订，自动检测翻译意图（阿拉伯语 / 法语 / 德语等），动态切换 Prompt。
多语言 反馈整合
08
📦 导出
最终 WorkflowResult 导出为 DOCX、JSON 或 Markdown，全链路完成，结构化输出就绪。
DOCX JSON Markdown

降级策略

每个 LLM 调用节点均内置 force_fallback 开关。未配置 LLM_API_KEY 时，系统自动切换至确定性模板引擎，保证全链路可演示。情报提取失败时回退至内置问界样例报告。

对话状态机

State Machine

ChatBot 对话生命周期的六个核心状态，具有确定性转换路径。

State -1
WELCOME
欢迎落地页，选择数据来源（样例 / 上传）。
State 0
TASK_START
收集任务目标，LLM 提取 TaskMetadata，生成澄清问题。
State 1
INTELLIGENCE_INPUT
接收澄清回答，确认情报底座，进入业务决策阶段。
State 2
BUSINESS_CONFIRM
展示推荐策略，人类调整或确认，触发 Director Insight。
State 3
DIRECTOR_INSIGHT
输出品牌/市场洞察，等待用户触发生成指令。
State 4
FEEDBACK_REVISE
多轮修订 + 翻译本土化循环，"导出"触发文件生成。

状态转换规则

当前状态触发词示例目标状态
WELCOME点击卡片TASK_START
TASK_START任何非空输入INTELLIGENCE_INPUT
INTELLIGENCE_INPUT确认 / 跳过 / ok / 开始BUSINESS_CONFIRM
BUSINESS_CONFIRM确认 / ok / 好的DIRECTOR_INSIGHT
DIRECTOR_INSIGHT生成 / 确认 / okFEEDBACK_REVISE
FEEDBACK_REVISE导出 / export / 完成终态 → 下载文件

Agents

专职 AI Agent 通过结构化数据契约协作，实现高质量 PR 生成。

输入
PRInsight TaskMetadata
输出

修订与翻译 Agent

PRDraftPackage ExpertReview[]

鉴权说明

设置环境变量 DEMO_ACCESS_TOKEN 后，FastAPI 要求请求头携带 Authorization: Bearer <token>。未设置时本地 demo 免鉴权。生产环境应替换为 API Gateway + SSO + Secret Manager。
