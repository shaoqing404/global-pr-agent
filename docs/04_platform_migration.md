# 平台集成与迁移方案 (Dify / Coze / n8n)

## 1. 系统定位

本项目提供的核心能力可通过 FastAPI 完美适配各类 AI 编排平台。在这种模式下，编排平台（如 Dify、Coze）负责业务入口与交互流程，而 Python 后端则作为**专业能力插件**，负责结构化数据处理、多 Agent 协作逻辑及复杂的文档渲染导出。

## 2. 集成至 Dify (Workflow 模式)

建议构建一个工作流应用：

```text
Start Form (任务配置)
  -> 知识库检索 (情报注入: 品牌手册/战略报告)
  -> 人类确认节点 (业务决策确认)
  -> LLM 节点 (Director 战略洞察)
  -> LLM 节点 (内容生成)
  -> 多 LLM 节点 (专家 Agent 审定)
  -> 迭代分支 (反馈修订)
  -> HTTP 节点 (调用 Python API 导出 DOCX/JSON)
  -> 结束
```

## 3. 集成至 Coze (Bot + Plugin 模式)

建议构建一个智能体协作模式：

```text
Bot: Global PR Agent
  -> 工作流：收集元数据与情报摘要
  -> 工作流：执行战略确认与洞察推演
  -> 插件：调用 FastAPI 进行多维度审定
  -> 插件：调用 FastAPI 生成并下载 DOCX
  -> 交互：支持多轮自然语言反馈与修订
```
**核心价值**：利用 Coze 的多模态交互能力，为业务团队提供一个可实时对话的 PR 助手入口。

## 4. 集成至 n8n (自动化流水线)

建议构建一个端到端的自动化流程：

```text
Webhook / 表单触发
  -> HTTP 节点 (调用 /api/generate-pr)
  -> IF 节点 (判断风险等级或评分)
      -> 分支 A (高风险)：发送至企业飞书/Slack 群组进行人工复审
      -> 分支 B (低风险)：直接归档
  -> 存储节点 (上传至云盘/知识库)
  -> 通知节点 (发送成品下载链接)
```
**核心价值**：适合连接企业现有的协作套件（如 Lark, Slack, Notion, Google Drive），实现 PR 生产的自动化流转。

## 5. 跨平台价值总结

- **统一标准**：通过定义结构化契约，确保了不同平台下 Agent 通讯的一致性。
- **能力沉淀**：将复杂的专家经验代码化，形成可复用的 AI 中台组件。
- **快速验证**：业务团队可根据不同场景选择最合适的交互入口（Bot 或 Flow），而核心逻辑无需重复开发。
