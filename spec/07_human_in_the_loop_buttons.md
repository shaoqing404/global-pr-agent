# Vue 前端交互重构补充说明 (Inner-Loop & Action Buttons)

## 1. 深度人机协作 (Human-in-the-Loop) 的痛点
在传统的 ChatBot 中，大模型容易在用户输入反馈后“擅作主张”直接推进流程。在企业级的 PR 生产管线中，这会导致业务人员产生强烈的“失控感”。

为了解决这个问题，我们在 `ChatInterface.vue` 的状态机中引入了**阶段锁死 (Gating) 与内循环 (Inner-loop)** 机制。

## 2. 解决方案：Action Buttons (按钮指令)
由于我们已经切换到了 Vue 3，我们不再需要像 Streamlit 那样强迫用户手打诸如“确认计划”、“确认生成”的硬指令（Hard Commands）。

我们通过在气泡消息下方动态挂载 **Action Buttons (操作按钮)** 来完美解决这个问题：
- 当模型完成一个阶段的推演（例如：完成了业务决策提炼），它会在回复下方渲染出一个蓝色的主操作按钮，例如 **[ 确认策略 ]**。
- **内循环 (Inner-Loop)**：如果用户不点击该按钮，而是继续在输入框打字（例如：“把目标受众改成年轻人”），系统会将其识别为**当前阶段的反馈修改**。AI 会吸收这个反馈，更新当前的 `human_notes`，并再次反问用户：“已调整，确认放行吗？”，并重新挂载 **[ 确认策略 ]** 按钮。
- **闸门放行 (Gating)**：只有当用户明确点击该按钮（或手动敲入与之对应的指令），状态机才会执行 `currentState.value = STATES.NEXT_STATE`，并触发下一个重量级的 Agent 任务（如 Director Insight 洞察生成）。

## 3. 实现细节 (`ChatInterface.vue`)
- **消息扩展**：`chatHistory` 中的消息对象新增了 `actions` 数组。
- **点击捕获**：用户点击按钮后，触发 `handleAction` 方法。该方法会在后台自动向输入框填充对应的“硬指令”（如“确认策略”）并执行发送，同时隐藏掉该条消息下方的按钮以防重复点击。

这种设计完美融合了“开放域聊天”的灵活性与“企业级工作流”的严谨性，是本次系统重构的一大亮点。
